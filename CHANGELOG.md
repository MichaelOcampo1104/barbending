- **Standalone viewer: the whole model in one `.html` file, with a section box (app)**:
  - Problem: once the modelling and the BBS are done there was no light way to save and share the model. The app needs `npm` and a server, the built app cannot be opened by double-click (its module scripts load from absolute `/assets/` paths), and glTF would store every bar as a mesh, carry no BBS and need a viewer site.
  - What it does: a new `⤓ Viewer` button in the header (next to `⤓ Project`) asks for a title (default `barbending model`, at most 80 characters; cancel aborts) and downloads ONE self-contained `barbending-viewer-<title>-<YYYYMMDD-HHMM>.html` that opens by double-click in any recent browser (Chrome and Edge 80+, Safari 16.4+, Firefox 113+) with no app, server or internet. The button reads `Building…` while it packs; if the generated template is missing, the alert says to run `npm run build:viewer`. The file holds the project as the app's own parametric rows (gzip + base64: about 22 KB for the Ent3 model) and a read-only viewer: 3D bars (the app's chunked line / tube renderer with its level of detail and end-on dots) and concrete, orbit / zoom / pan, Iso and the six true orthographic views with the projection pill, click a bar for its details, the sortable, filterable BBS table (a click selects and zooms), the diameter legend, a Concrete toggle, and `⤓ Project`, which hands back the embedded project as a `.json`. The same file opens in the app again: `⤒ Project` and `⤒+ Insert` now accept `.html` (a file that is not a viewer file, or was made by a newer viewer, is refused with a message), so it is also a save. Left out on purpose: the IFC model (27 MB would defeat the point), drawing the reference lines (their data is kept in the file), measuring, editing, hosting and share links.
  - Section box in the viewer (`◫ Section` in the header, a panel at the top left): the app's controls, rebuilt on plain three.js. Faces: six axis-coloured push / pull grips that keep a constant size on screen (14 px, with a pick area twice that; a press on a grip never reaches the orbit controls; pointer events, so mouse, touch and pen), never thinner than 50 mm; Move and Rotate through three's `TransformControls`; Fit box (the model bounds plus padding), Test cut (a third of each size around the same centre), Solid cut (the app's stencil technique: the cut faces of the concrete are filled; rebar is not capped), `👁 Box` (hides the box, the cut stays) and a size readout. A click on a bar outside the box selects nothing. The box is not saved in the file.
  - Implementation: the pure section-box maths moved out of `SectionBox.jsx` into `src/viewer/sectionBoxMath.js` and is shared by the app and the viewer (the refactor is pinned by a unit test that equals the old drag code bit for bit over 2,000 random cases, and by a new face-grip drag assertion in `check_views.mjs` that gives the same numbers before and after). New `src/standalone/`: `pack.js` and `codec.js` (the format: a generated HTML template with two tokens, the title and the data, filled in by `packViewerHtml`; `extractProjectFromHtml` reads it back), `exportViewer.js` (fetches the template; a dev server answers an unknown path with `index.html` and status 200, so it looks for the template's own tokens, not the status), and the viewer itself (`viewer.js`, `sectionBox.js`, `template.html`): a vanilla-JS page that reuses the app's own pure modules (`buildField`, `FieldView`, `pickField`, `cameraMath`, `sectionPlanes`, `stencilMats`, `csv.js`, ...) so geometry and numbers cannot drift from the app. `scripts/build-viewer.mjs` bundles it with Vite's library mode into `public/viewer-template.html` (git-ignored, copied to `dist/`); `npm run build:viewer` runs it, and so do `predev` and `prebuild`. The dev server does not watch `src/standalone/`: after changing it run `npm run build:viewer` and reload. The test hooks (`window.__viewer`) and a readable canvas exist only with `?autotest`. README, `agent.md`, `overview.md` and the perf README describe it.

- **Box & Lasso select: a toolbar choice and one exact rule for both (app)**:
  - The viewport toolbar's single Box button becomes a pair, `⊞ Box [Shift+B]` and `➰ Lasso [Shift+L]` (a "N selected" pill follows it, the left-panel tip has both buttons, and the hint bar names the armed tool). The store's `selectTool` (`null | 'box' | 'lasso'`, with `toggleSelectTool`) replaces the `boxSelect` flag. Both tools are one-shot, as Box was: one LMB drag draws the shape and selects, then the tool disarms; Ctrl adds to the selection, Esc cancels, and a click without a drag (or a scribble shorter than 8 px) only disarms. The lasso is a free-form loop drawn as a dashed SVG outline with a light fill; it closes back to its start, is simplified to 1 px before testing, and follows the even-odd rule if it crosses itself.
  - One rule for both shapes, which changes Box: a BBS row is selected when any segment of any copy of any of its bars, projected through the active camera, lies inside the shape, crosses its outline or passes within 2 px (`TOUCH_TOL_PX`) of it. The old Box rule was the row's projected bounding box, so a box in the gap between the copies of a wide set picked the set; now it selects nothing, and an end-on bar (a dot) is selected by a shape around it. Perspective and orthographic share the code (it only needs the view-projection matrix), with near / far clipping so nothing behind a perspective camera is picked; hidden bars, bars of hidden members and bars inside them are skipped as before.
  - Implementation: new pure `src/viewer/regionSelect.js` (the shapes, segment-vs-shape tests and `selectBarsInRegion`; per-row geometry cached in a `WeakMap` keyed by the row object, and a bounding-box prefilter that uses the new `distOffsetExtents` in `shapes.js`, so no distribution grid is built just to measure a row); `RegionSelect` in `Scene.jsx` replaces `BoxSelect`; `App.jsx` has the toolbar, the hint, the left-panel buttons and Shift+L.
